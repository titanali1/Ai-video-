# Deisa — استودیوی خلاقیت هوش مصنوعی

یک نمونه‌ی موبایل‌محور و قابل نصب (PWA) به زبان فارسی و راست‌چین برای اپ اندروید تولید محتوای هوش مصنوعی. نشان Deisa یک قاب ویدیو و دکمه‌ی پخش را با گره‌ها و مسیرهای مدار هوش مصنوعی ترکیب می‌کند. شامل داشبورد، فرم تولید کلیپ کوتاه از متن یا تصویر، ابزار تولید تصویر، ابزار صدا و گویندگی و کتابخانه‌ی پروژه‌ها است. تولید واقعی تصویر/ویدیو از طریق gateway اختیاریِ این مخزن انجام می‌شود؛ صداسازی هنوز متصل نیست.

## اجرا

```bash
python3 -m http.server 8000 --bind 0.0.0.0
```

سپس `http://localhost:8000` را باز کنید. در مرورگر اندروید می‌توان از گزینه‌ی «افزودن به صفحه‌ی اصلی» برای نصب PWA استفاده کرد.

## ساخت APK اندروید

پروژه‌ی بومی WebView در پوشه‌ی `android/` قرار دارد؛ فایل‌های وب داخل APK به‌صورت محلی سرو می‌شوند و انتخاب تصویر با انتخاب‌گر سیستمی است، بدون مجوز کلی حافظه. تنظیمات ساخت: حداقل Android 5.0 / API 21، `compileSdk 36` و `targetSdk 36` برای Android 16؛ اپ از API اختصاصی 37 استفاده نمی‌کند و برای نصب روی نسخه‌های جدیدتر نیز محدودیت نسخه‌ی سیستم ندارد.

با JDK 17، Gradle 9.6.0، Android SDK Platform 36 و Build Tools 36.0.0:

```bash
cd android
./build-apk.sh
```

برای ساخت variant انتشارِ بدون امضا، `./build-release-apk.sh` را اجرا کنید؛ امضای نهایی به keystore نیاز دارد. فایل فعلی `Deisa.apk` یک release APK امضاشده برای نصب مستقیم است. کلید موقت CI برای انتشار فروشگاهی یا به‌روزرسانی بعدی نگهداری نمی‌شود؛ برای توزیع پایدار باید keystore خصوصی متعلق به صاحب اپ تنظیم شود. اگر نسخه‌ی debug قبلی نصب است، پیش از نصب این APK آن را حذف کنید چون گواهی امضایش متفاوت است.

### نصب در Xiaomi / MIUI / HyperOS

APK را در حافظه‌ی گوشی باز کنید و برای همان برنامه‌ای که فایل را باز می‌کند، اجازه‌ی «Install unknown apps / نصب برنامه‌های ناشناس» را در تنظیمات فعال کنید. اگر اسکن امنیتی MIUI هشدار داد، فقط در صورتی ادامه دهید که فایل را از منبع مورد اعتماد گرفته‌اید. محدودیت‌های نصب ناشناس و سیاست‌های امنیتی Xiaomi از داخل اپ قابل حذف نیستند. این ساخت برای Android 5.0 به بالا هدف‌گذاری شده؛ سازگاری با همه‌ی رام‌ها و دستگاه‌های قدیمی بدون آزمون روی خود دستگاه قابل تضمین نیست.

## اتصال تولید واقعی تصویر و ویدیو

برنامه می‌تواند به دو مسیر وصل شود:

- **ComfyUI خودمیزبان** برای تصویر و ویدیو (از جمله workflowهای مدل‌های متن‌باز). API آن هزینه/سهمیه‌ی هر درخواست ندارد، اما اجرای مدل به GPU، حافظه، زمان و برق خودتان نیاز دارد؛ پس «ابر رایگان و نامحدود» نیست. ComfyUI را مستقیماً روی اینترنت باز نکنید.
- **Hugging Face Inference Providers** برای تصویر با token سمت سرور و مدل FLUX.1-schnell. اعتبار رایگان ماهانه محدود است (مستندات فعلی HF مقدار پایه‌ی ۰٫۱۰ دلار در ماه را اعلام می‌کند و ممکن است تغییر کند). برنامه تولید ویدیوی ابری را فعال نمی‌کند تا هزینه‌ی partner ناخواسته ایجاد نشود؛ ویدیو از ComfyUI محلی انجام می‌شود. [صفحه‌ی قیمت‌گذاری HF](https://huggingface.co/docs/inference-providers/pricing).

### اجرای gateway در کنار رابط

Python 3.10+ لازم است. در سیستم سروری که از GPU/ComfyUI یا اینترنت دسترسی دارد:

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

مقادیر `.env` را تنظیم کنید و سپس `python server.py` را اجرا کنید. این سرور هم رابط وب و هم مسیرهای `/api/providers` و `/api/generate` را ارائه می‌کند؛ برای اجرای فقط UI بدون API، دستور `python3 -m http.server 8000 --bind 0.0.0.0` همچنان کافی است.

برای Hugging Face، `HF_TOKEN` را با یک token محدودِ مجوز Inference Providers پر کنید. token را داخل APK یا مرورگر قرار ندهید. برای ComfyUI، workflow تصویری و ویدیویی را از ComfyUI با فرمت **API** export کنید و فایل‌ها را در `workflows/` بگذارید. در `.env`، شناسه‌ی node متن، input متن، node خروجی و در صورت image-to-video شناسه‌ی node تصویر را مشخص کنید. نام مدل‌ها و ساختار گره‌ها به workflow و افزونه‌های نصب‌شده‌ی ComfyUI بستگی دارد؛ نمونه‌ی workflow سخت‌افزار/مدل را دانلود یا نصب نمی‌کند.

در Deisa از «اتصال سرویس‌ها» آدرس gateway و در صورت نیاز `DEISA_API_KEY` را ذخیره کنید. برای استفاده از APK، gateway باید از گوشی قابل دسترس باشد؛ برای دسترسی اینترنتی HTTPS و کلید قوی تنظیم کنید. API، کلید مدل‌ها را از سرور می‌خواند. نمونه‌ی `.env.example` را قبل از انتشار ویرایش کنید و هرگز `.env` واقعی را commit نکنید.

فعلاً هر درخواست ویدیو **یک کلیپ خروجیِ مطابق محدودیت مدل/workflow** می‌سازد، نه یک فیلم بلند ۶۰ دقیقه‌ای یک‌جا؛ ویدیوهای بلند باید از کلیپ‌های متعدد تدوین شوند. تولید صدا نیز هنوز به provider وصل نیست.
